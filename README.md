# OMP Context

[![Проверки](https://github.com/LenderAuss/OMP-context/actions/workflows/test.yml/badge.svg)](https://github.com/LenderAuss/OMP-context/actions/workflows/test.yml)

Переносимая сборка OMP с управлением контекстом, **общей локальной памятью между сессиями** и Graphify. Версия 0.1.0, beta. Исходники: [LenderAuss/OMP-context](https://github.com/LenderAuss/OMP-context).

Сборка устанавливает OMP, Python и Graphify, создаёт отдельный профиль и команду `omp-kit`. Обычный `omp`, его аккаунты и сессии не заменяются. Новому пользователю остаётся войти в собственный аккаунт провайдера.

## Установка

Клонируйте репозиторий и запустите установщик. Если Git не установлен, скачайте ZIP из [релиза v0.1.0 beta](https://github.com/LenderAuss/OMP-context/releases/tag/v0.1.0) или [текущие исходники](https://github.com/LenderAuss/OMP-context/archive/refs/heads/main.zip), распакуйте его, откройте терминал в распакованной папке и выполните только последнюю команду для своей ОС. В релизе есть файл `SHA256SUMS.txt` для проверки архивов.

**macOS / Linux / WSL:**

```sh
git clone https://github.com/LenderAuss/OMP-context.git
cd OMP-context
sh install.sh
```

**Windows, PowerShell:**

```powershell
git clone https://github.com/LenderAuss/OMP-context.git
cd OMP-context
powershell -NoProfile -ExecutionPolicy Bypass -File .\install.ps1
```

Флаг ExecutionPolicy действует на этот процесс, а не меняет политику Windows навсегда. Установщик не требует прав администратора. Он проверяет SHA-256 OMP и uv, ставит управляемый Python и отдельное окружение Graphify с хешами зависимостей. На macOS дополнительно проверяет подпись OMP через codesign.

Откройте новый терминал:

```sh
omp-kit doctor
omp-kit
```

Внутри OMP:

```text
/login zai
/model
```

Для **Z.AI Coding Plan** нужен свой API key этой подписки. Вход выполняется штатным интерфейсом OMP; ключ не вставляется в установщик, GitHub или командную строку. Для других провайдеров откройте `/login`, выберите поддерживаемый способ входа, затем `/model`. Подписка на веб-чат не обязательно даёт доступ через CLI — это зависит от конкретного провайдера и способа авторизации. [Документация OMP](https://github.com/can1357/oh-my-pi/blob/v18.14.0/docs/providers.md), [Z.AI](https://docs.z.ai/devpack/tool/others).

Профиль по умолчанию использует `yolo`: команды и запись автоматически разрешены. Это соответствует исходной настройке сборки. Для другого режима при первой установке:

```sh
sh install.sh --permissions write
```

Windows: добавьте `-Permissions write`. Существующая конфигурация при повторной установке сохраняется. Подагенты через `task` отключены; компьютерное управление и фоновый прогрев кеша отключены.

## Как работает память

1. В ходе существенной работы модель сохраняет краткие заметки: цель, ограничения, решения, прогресс, следующие шаги. Ссылки на записи диалога проверяются.
2. Проверенные по структуре заметки автоматически попадают в локальную SQLite-базу. Отменённые решения не выдаются как текущие.
3. В новой сессии подходящие записи находятся по словам запроса и подставляются небольшим блоком с проектом, датой и источниками. Поиск не вызывает отдельную модель.
4. Из базы строится **один общий граф памяти** для Graphify. Графы кода и документации конкретных проектов используются отдельно.

Пример: в одной сессии сохранить выбор PostgreSQL и незавершённую миграцию, в новой спросить о той же системе и миграции. Агент получает подходящие записи и может открыть источники. Если данных нет или решения противоречат друг другу, он должен сказать об этом, а не восстанавливать детали догадкой.

Поиск сейчас лексический: SQLite FTS5, префиксы и небольшой русско-английский словарь. Это не полноценная семантическая модель. Важные факты должны попасть в заметки или быть явно сохранены через `shared_memory`; весь разговор автоматически в базу не копируется. Для стабильных настроек инструмент поддерживает ключи вроде `deploy.target`, источники и явное `supersedes`. Автоматически распознать любые смысловые противоречия он не умеет.

Память локальная **на каждом устройстве**, синхронизации между устройствами нет. Оригинальные сессии сохраняются в OMP. Вызов `/new` создаёт самостоятельный диалог, но теперь может получить релевантные факты из общей памяти. Чужая старая задача не становится автоматически текущей целью.

## Полезные команды

Внутри OMP:

| Команда | Назначение |
|---|---|
| `/context-status` | Состояние заметок и использования контекста |
| `/context-checkpoint` | Попросить модель обновить заметки |
| `/compact` | Сменить окно контекста в текущем диалоге |
| `/memory-status` | Состояние общей памяти без вызова модели |
| `/memory-search слова` | Локальный поиск без вызова модели |

В терминале:

```sh
omp-kit memory status
omp-kit memory search "миграция PostgreSQL"
omp-kit memory evidence MEMORY_ID
omp-kit memory forget MEMORY_ID
omp-kit memory graph
graphify-kit --version
```

Для агента доступны `shared_memory` (поиск, источники, сохранение, замена, забывание, выбор проекта), `context_probe` и `project_graph`. При работе в общей папке многих проектов нужно выбрать реальный проект через `shared_memory action=project`; можно задать его короткие названия/алиасы.

`project_graph` возвращает ограниченный фрагмент существующего графа, не весь JSON. Он показывает дату графа и признаки устаревших источников. Создание графа кода/документов — отдельная операция для выбранного проекта по [инструкциям Graphify](https://github.com/Graphify-Labs/graphify); установщик не сканирует автоматически все проекты, архивы, `.env` и домашний каталог.

## Где находятся данные

По умолчанию:

- macOS/Linux: `~/.local/share/omp-context-kit/` (или XDG_DATA_HOME).
- Windows: `%LOCALAPPDATA%\OmpContextKit\`.
- `state/agent/` — отдельный профиль OMP, аккаунты и сессии.
- `state/memory.sqlite3` — общая память.
- `state/memory-graph/graphify-out/graph.json` — производный общий граф.

В GitHub распространяется только программа. Установщик не содержит и не переносит чужие аккаунты, память, ключи или диалоги. Данные защищаются правами каталога; это **не шифрование базы**. Релевантные извлечённые фрагменты отправляются выбранному AI-провайдеру вместе с запросом, как обычный контекст. Не сохраняйте секреты в заметках: фильтр типичных ключей не обнаруживает все возможные секреты.

`memory forget` убирает запись из поиска и проекции графа, но не стирает исходный диалог и не является гарантированным физическим уничтожением старых страниц SQLite/резервных копий.

## Платформы и проверка

| Платформа | Статус версии 0.1.0 |
|---|---|
| macOS Apple Silicon | Реальная установка, интеграционные проверки и GitHub Actions прошли |
| macOS Intel | Есть соответствующий бинарник и ветка установщика; отдельный Intel Mac не проверялся |
| Linux x64 | Установка и восстановление памяти между сессиями прошли в Ubuntu CI |
| Linux ARM64 / WSL | Ветки установщика подготовлены; отдельные ARM64/WSL-хосты не проверялись |
| Windows x64 | Нативный Windows CI проверил PowerShell-установку, `.cmd`-запуск и восстановление памяти |
| Windows ARM64 | Использует x64-совместимость Windows; отдельное ARM-устройство не проверялось |
| Alpine/musl | Есть бинарник и зависимости; нужны системные libstdc++/libgcc; отдельный Alpine-хост не проверялся |

Это сборка для настольных ОС и серверов, не нативное приложение для iOS/Android. [GitHub Actions](https://github.com/LenderAuss/OMP-context/actions/workflows/test.yml) проверяет чистую установку и два независимых процесса OMP на macOS ARM64, Ubuntu x64 и Windows x64. Непроверенные архитектуры отмечены отдельно в таблице.

```sh
python3 -m unittest discover -s tests -p 'test_*.py'
node --test tests/*.test.mjs
python3 tests/integration_rpc.py
```

Последняя команда использует установленный OMP и локальный тестовый HTTP-провайдер: проверяет сохранение заметок и автоматическое восстановление фактов в **другом новом процессе**, без платных AI-вызовов. Отдельный живой тест использует существующий аккаунт стандартного OMP и расходует его квоту: `python3 tests/integration_rpc.py --live PROVIDER/MODEL`. Профиль теста и память искусственные; ключи не копируются.

На macOS также выполнен живой тест GLM-5.3 (low): новая независимая сессия автоматически восстановила PostgreSQL, порт, запрет production и незавершённую миграцию. Это небольшой сценарий, а не доказательство безошибочности на любом долгом проекте.

## Обновление, настройки и удаление

Повторите установку из новой версии пакета. Конфигурация, аккаунты и память сохраняются; изменённый пользователем launcher не перезаписывается молча. Параметры `--prefix`, `--bin-dir`, `--no-path`, `--dry-run` доступны через `python3 install.py --help`. Windows-обёртка поддерживает `-Prefix`, `-BinDir`, `-NoPath`, `-DryRun`.

Чтобы убрать команды сборки и сохранить данные: `python3 uninstall.py`. Каталог с памятью/авторизацией автоматически не удаляется. Обычный OMP не откатывается и не удаляется.

Сжатие использует экспериментальный notes-backed режим OMP: порог 120k, недавний контекст 20k, исходная история доступна через `history://current/full`. Валидатор проверяет структуру, ссылки и давность заметок относительно убираемых сообщений. Он не доказывает смысловую полноту и не гарантирует отсутствие галлюцинаций. Экономию токенов нужно измерять на целой рабочей задаче, включая retrieval и checkpoint; проценты экономии не заявляются.
